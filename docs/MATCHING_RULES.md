# Matching Rules

## 1. 목적

이 문서는 사용자 프로파일과 채용공고를 비교할 때 사용하는 첫 번째 MVP 규칙을 정의한다.

첫 MVP의 목표는 정밀한 합격 확률을 계산하는 것이 아니라 다음 질문에 일관되게 답하는 것이다.

- 공고의 각 요구사항을 뒷받침하는 사용자 증거가 있는가
- 직접 증거와 유사 증거를 구분할 수 있는가
- 확인된 부족과 정보 부족을 구분할 수 있는가
- 지금 지원할 가치가 있는지 근거와 함께 설명할 수 있는가

## 2. MVP 범위

포함:

- 필수 조건 비교
- 우대 조건 비교
- 경력, 기술, 프로젝트, 행동 사례의 증거 연결
- 경력 연수, 근무 지역, 고용 형태 같은 지원 조건 확인
- 요구사항별 판정과 지원 판단

제외:

- 합격 가능성 예측
- 검증되지 않은 적합도 백분율
- 채용시장 전체 통계
- 여러 채용사이트의 자동 수집
- 자동 입사지원

## 3. 입력

첫 MVP는 다음 두 입력을 사용한다.

- `data/user_profile.example.json` 구조를 따르는 사용자 프로파일
- `data/job_posting.example.json` 구조를 따르는 채용공고

입력에서 확인되지 않은 정보는 임의로 보완하지 않는다.

## 4. 비교 단위

채용공고의 다음 항목을 각각 독립적인 비교 단위로 처리한다.

1. `requirements`의 필수 조건
2. `preferred_qualifications`의 우대 조건
3. `experience`의 경력 조건
4. `education`의 학력 조건
5. `employment`의 고용 형태
6. `location`의 근무 위치와 원격 여부
7. `responsibilities`의 주요 업무

필수 조건과 우대 조건을 하나의 목록으로 합치지 않는다.

## 5. 증거 우선순위

같은 요구사항에 여러 증거가 연결될 때 다음 순서를 우선한다.

1. 실제 업무에서 사용하거나 달성한 증거
2. 완료되었거나 동작이 확인된 프로젝트 증거
3. 유사한 문제를 해결한 행동 사례
4. 기본 사용 경험
5. 현재 학습 중인 내용
6. 설치 또는 화면 확인 수준의 노출 경험
7. 자기평가, 관심 또는 검사 결과

검사 결과와 업무 선호는 기술 보유 여부를 증명하지 않는다.

## 6. 증거 직접성

요구사항과 사용자 증거의 관계를 다음과 같이 구분한다.

- `exact`: 같은 기술, 업무 또는 결과를 직접 확인할 수 있음
- `equivalent`: 명칭은 다르지만 공고가 인정하는 동등 경험에 해당함
- `related`: 일부 개념이나 행동은 관련되지만 요구 수준을 직접 증명하지 못함
- `none`: 관련 증거가 확인되지 않음

기술 별칭은 사전에 정의된 목록만 사용한다. 예를 들어 `REST API`와 `RESTful API`는 같은 개념으로 정규화할 수 있지만, `서버 운영`을 근거 없이 `AWS 운영`으로 바꾸지 않는다.

## 7. 요구사항별 판정

각 요구사항은 다음 중 하나로 판정한다.

### strong_match

다음 조건을 모두 만족할 때 사용한다.

- `exact` 또는 명시적으로 인정되는 `equivalent` 증거가 있다.
- 실무 또는 동작이 확인된 프로젝트에서 사용했다.
- 공고가 요구한 수준과 같거나 그보다 높은 증거가 있다.

### match

다음 중 하나에 해당할 때 사용한다.

- 직접 관련된 경험이 있으나 범위나 깊이가 공고와 완전히 같지는 않다.
- 유사 기술을 사용했고 전환 가능성을 설명할 근거가 있다.
- 공고가 동등 경험을 허용하고 이를 뒷받침하는 증거가 있다.

### partial

다음 중 하나에 해당할 때 사용한다.

- 관련 경험은 있지만 요구 수준보다 낮다.
- 일부 하위 업무만 수행했다.
- 학습 또는 기본 사용 경험만 있고 실무나 프로젝트 증거가 부족하다.

공고가 실제 사용 경험을 요구하는 경우 설치 또는 화면 확인 수준의 `exposure`만으로는 `partial`로 판정하지 않는다.

### gap

다음 조건을 모두 만족할 때만 사용한다.

- 현재 프로파일에서 요구 수준에 미치지 못한다는 사실을 확인할 수 있다.
- 필수 자격증 미보유, 요구 연수 미달처럼 비교 가능한 정보가 있다.

프로파일에 기술이 적혀 있지 않다는 이유만으로 `gap`으로 판정하지 않는다.

### unknown

다음 중 하나에 해당할 때 사용한다.

- 사용자 정보가 없어 보유 여부를 확인할 수 없다.
- 공고의 요구 수준이 모호하다.
- 기술명이나 업무 의미를 안전하게 정규화할 수 없다.
- 원문이 부족해 필수 조건인지 판단할 수 없다.

`unknown`은 자동으로 `gap`으로 변환하지 않는다.

## 8. 조건 중요도

조건 중요도는 다음 순서로 처리한다.

1. 법적 자격, 필수 자격증, 필수 언어 등 지원 불가능 여부를 결정하는 조건
2. 공고에 명시된 필수 기술과 필수 경험
3. 주요 업무를 수행하는 데 직접 필요한 역량
4. 우대 조건
5. 단순 언급 기술과 조직 소개 문구

우대 조건 부족만으로 지원을 보류하지 않는다.

## 9. 지원 가능 조건

역량 적합도와 지원 가능 조건을 분리해 기록한다.

지원 가능 조건 예시:

- 최소 경력 연수
- 필수 학력 또는 자격
- 근무 가능 지역
- 고용 형태
- 필수 언어
- 출근 또는 원격근무 조건

사용자 프로파일의 선호가 `hard_constraint`로 명시되지 않았다면 단순 선호 불일치만으로 지원 불가 판정을 내리지 않는다.

## 10. 지원 판단

최종 판단은 다음 중 하나를 사용한다.

### 적극 지원

- 확인된 필수 조건 `gap`이 없다.
- 핵심 업무와 필수 조건 대부분에 직접 증거가 있다.
- 확인된 지원 불가 조건이 없다.

### 지원 추천

- 확인된 필수 조건 `gap`이 없다.
- 일부 `partial` 또는 `unknown`이 있지만 지원과 병행해 확인하거나 보완할 수 있다.
- 역할의 핵심 업무와 연결되는 실제 증거가 있다.

### 조건부 지원

- 필수 조건에 `partial` 또는 중요한 `unknown`이 있다.
- 동등 경험 인정 여부나 공고 해석을 추가로 확인해야 한다.
- 확인 결과에 따라 지원 판단이 달라질 수 있다.

### 역량 보완 후 지원

- 핵심 필수 조건에 확인된 `gap`이 있다.
- 짧은 확인만으로 해결되지 않고 증명 가능한 보완이 필요하다.

### 현재는 우선순위 낮음

- 확인된 지원 불가 조건이 있다.
- 핵심 업무와 연결되는 증거가 매우 적다.
- 현재 목표 직무와의 거리가 크고 더 적합한 공고에 시간을 쓰는 편이 합리적이다.

이 판단은 합격 가능성 예측이 아니라 현재 프로파일과 공고의 비교 결과다.

## 11. 판단 근거 기록

각 요구사항의 결과에는 최소한 다음 정보를 남긴다.

- 공고 요구사항 원문 또는 짧은 근거 문구
- 요구사항 유형과 중요도
- 판정
- 연결된 사용자 증거
- 증거 수준과 직접성
- 판단 이유
- 확인되지 않은 점
- 다음 확인 또는 보완 행동

Agent의 해석은 공고 원문과 사용자 데이터에서 확인된 사실과 분리한다.

## 12. 예제 공고의 기대 판정

현재 예제 데이터 기준의 기대 결과는 다음과 같다.

- Python 개발 경험: `strong_match`
  - Tech News Automation에서 Python을 사용한 프로젝트 증거가 있음
- REST API 연동 경험: `strong_match`
  - Gemini API와 Slack Webhook 연동 증거가 있음
- 자동화 프로젝트 경험: `strong_match`
  - 수집, 중복 방지, 요약, 예약 실행, 전달까지 구현한 프로젝트 증거가 있음
- Docker 사용 경험 우대: `gap`
  - 설치 경험만 있고 컨테이너 실행 또는 프로젝트 사용 경험이 없음을 확인함
- AWS 운영 경험 우대: `gap`
  - AWS CLI 화면을 확인한 적만 있고 직접 사용 경험이 없음을 확인함
- LLM API 활용 경험 우대: `strong_match`
  - Gemini API를 사용한 프로젝트 증거가 있음

## 13. 첫 구현 완료 기준

다음 조건을 모두 만족하면 첫 매칭 기능을 완료한 것으로 본다.

- 모든 필수 조건에 하나의 판정이 있다.
- 모든 판정에 공고 근거가 연결된다.
- `strong_match`, `match`, `partial`에는 사용자 증거가 연결된다.
- `gap`과 `unknown`이 구분된다.
- 우대 조건 부족이 필수 조건 부족처럼 처리되지 않는다.
- 지원 판단에 사용한 핵심 근거가 표시된다.
- 동일한 입력을 다시 처리했을 때 핵심 판정이 유지된다.
- 확인되지 않은 사용자 경험이나 기술을 생성하지 않는다.

4. 실제 공고 1건으로 판정 규칙을 검토한다.
