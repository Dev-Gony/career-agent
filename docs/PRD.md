# Career Agent PRD

## 1. 프로젝트 개요

### 프로젝트명
Career Agent

### 한 줄 설명
개인의 성향, 경력, 기술, 프로젝트와 실제 채용공고를 비교하여 직무 적합도, 부족 역량, 학습 방향, 포트폴리오 개선 방향, 지원 우선순위를 제안하는 개인용 AI 취업 준비 에이전트.

### 현재 범위
초기에는 본인 1명이 사용하는 개인용 MVP로 개발한다.

실제 사용을 통해 유용성을 검증한 뒤 채용공고 자동 수집, 정기 브리핑, 시장 요구 역량 분석 등으로 단계적으로 확장한다.

## 2. 문제 정의

현재 취업 준비 과정에는 다음 문제가 있다.

- 어떤 직무가 나와 잘 맞는지 판단하기 어렵다.
- 성격검사, 적성검사, 경력, 프로젝트, 기술 정보가 여러 자료에 흩어져 있다.
- 채용공고마다 요구사항을 반복해서 읽고 비교해야 한다.
- 부족한 역량을 발견해도 무엇부터 보완해야 할지 결정하기 어렵다.
- 어떤 포트폴리오가 실제 취업에 도움이 되는지 판단하기 어렵다.
- 신규 채용공고를 계속 찾아보고 정리하는 과정이 반복적이다.

## 3. 핵심 목표

이 프로젝트의 목표는 다음 질문에 반복적으로 답할 수 있는 시스템을 만드는 것이다.

1. 이 직무가 나와 왜 맞는가?
2. 왜 맞지 않는가?
3. 현재 부족한 역량은 무엇인가?
4. 무엇을 먼저 공부해야 하는가?
5. 기존 포트폴리오를 어떻게 개선하면 되는가?
6. 지금 이 공고에 지원할 가치가 있는가?

## 4. 사용자

초기 사용자: 본인 1명

주요 관심 직무 후보:

- AI Automation / Workflow Engineer
- AI Solutions Engineer
- Forward Deployed Engineer 계열
- Enterprise Solution / ITSM / Workflow Automation
- Cloud / Automation
- Data + Automation 계열

직무 후보는 고정값이 아니라 실제 채용공고 분석 결과에 따라 계속 수정할 수 있다.

## 5. 판단 원칙

Agent는 다음 우선순위로 사용자 정보를 해석한다.

1. 실제 경력과 프로젝트
2. 실제 행동 사례와 문제 해결 경험
3. 기술 사용 수준과 증거
4. 직무/적성 검사
5. 성격 및 강점 검사

성격검사 하나만으로 직무를 추천하거나 배제하지 않는다.

## 6. 기본 사용자 흐름

    사용자 프로파일
            |
            v
    관심 직무 또는 채용공고
            |
            v
    채용공고 요구사항 추출
            |
            v
    사용자 경험 및 역량과 비교
            |
            v
    적합 요소 / 부족 요소 분석
            |
            v
    학습 우선순위 제안
            |
            v
    포트폴리오 개선 방향 제안
            |
            v
    지원 판단 및 근거 제공

궁극적인 사용자 인터페이스는 Slack 또는 Telegram 대화다. 사용자가 원하는 직무·경력 조건을 메시지로 설명하거나 이력서, 포트폴리오와 경력기술서를 첨부하면 Agent가 이를 비공개 사용자 프로필로 구조화한다. Agent는 그 프로필에서 검색 직무와 표현을 도출하고, 이용이 허용된 공식 API·RSS·기업 채용 소스에서 현재 공고를 발견하며, 적합한 공고와 판단 근거를 다시 대화로 전달한다. 사용자 자료에 충분한 근거가 있으면 직무 키워드를 매번 다시 요구하지 않는다.

## 7. MVP 범위

첫 번째 버전에서는 채용사이트 자동 수집 기능을 구현하지 않는다.

먼저 사용자가 직접 넣은 채용공고를 분석하여 핵심 판단 기능이 실제로 도움이 되는지 검증한다.

### MVP 입력

- 구조화된 사용자 프로파일
- 채용공고 원문 또는 복사한 JD

### MVP 출력

- 회사명
- 직무명
- 주요 업무
- 필수 역량
- 우대 역량
- 경력 조건
- 요구 기술
- 잘 맞는 부분
- 부족한 부분
- 직무 적합도와 근거
- 학습 우선순위
- 포트폴리오 개선 제안
- 지원 판단

## 8. 핵심 기능

### 기능 1. 채용공고 구조화

채용공고에서 다음 항목을 추출한다.

- 회사명
- 직무명
- 주요 업무
- 필수 조건
- 우대 조건
- 요구 기술
- 경력 수준
- 도메인 지식
- 협업 및 커뮤니케이션 요구

### 기능 2. 사용자 프로파일 비교

채용공고와 다음 사용자 데이터를 비교한다.

- 경력
- 프로젝트
- 기술
- 문제 해결 사례
- 업무 성향
- 관심 직무

### 기능 3. 적합도 분석

적합도는 숫자만 제공하지 않는다.

반드시 다음을 함께 제공한다.

- 높은 적합 근거
- 부분 적합 근거
- 부족한 근거
- 판단에 사용한 사용자 경험

### 기능 4. 역량 갭 분석

부족한 역량을 나열하고 우선순위를 구분한다.

예:

- 즉시 보완 필요
- 지원과 병행하여 보완 가능
- 우대사항 수준
- 현재 우선순위 낮음

### 기능 5. 학습 추천

학습 항목은 단순 기술 목록이 아니라 실제 결과물과 연결한다.

예:

    Docker 공부

보다

    기존 Tech News Automation을 Docker로 실행하고 재현 가능한 배포 구조를 만든다.

처럼 증명 가능한 결과물을 우선한다.

### 기능 6. 포트폴리오 추천

새 프로젝트를 무조건 추가하지 않는다.

우선순위:

1. 기존 프로젝트에 부족한 역량 추가
2. 기존 프로젝트를 더 깊게 개선
3. 그래도 증명하기 어려운 경우에만 새 프로젝트 제안

### 기능 7. 지원 판단

다음 중 하나로 제안한다.

- 적극 지원
- 지원 추천
- 조건부 지원
- 역량 보완 후 지원
- 현재는 우선순위 낮음

합격 가능성을 확정적으로 예측하지 않는다.

## 9. MVP 성공 기준

실제 관심 채용공고 10개 이상을 분석한다.

다음 조건을 만족하면 다음 단계로 넘어간다.

- 결과를 읽고 지원 여부를 결정하는 데 실제 도움이 된다.
- 반복 분석에서도 비슷한 기준이 유지된다.
- 부족 역량 제안이 과도하게 넓지 않다.
- 학습 추천이 실제 실행 가능한 결과물과 연결된다.
- 포트폴리오 추천이 기존 작업과 연계된다.

## 10. 이후 확장

### 2단계

채용공고 자동 수집

검토 대상:

- 사람인
- 잡코리아
- 인크루트
- 원티드
- 기업 채용 페이지
- 공개 채용 API 또는 데이터

각 사이트의 정책을 확인한 뒤 적법하고 안정적인 방식만 사용한다.

### 3단계

정기 채용공고 분석

    신규 공고 수집
    -> 중복 제거
    -> 사용자 적합도 분석
    -> 추천 공고 선정
    -> 저장

### 4단계

정기 취업 브리핑

예:

    오늘의 추천 채용공고
    직무 적합도
    추천 이유
    부족 역량
    지원 우선순위

전달 수단 후보:

- Slack
- 이메일
- 웹 대시보드

### 5단계

채용시장 요구 역량 분석

누적된 공고에서 기술 요구 빈도를 계산한다.

예:

    Python 72%
    AWS 61%
    Docker 58%
    SQL 47%
    FastAPI 39%

이 데이터를 개인 프로파일과 비교하여 학습 및 포트폴리오 우선순위를 조정한다.

## 11. 기술 후보

아직 확정하지 않는다.

- Python
- Gemini 또는 기타 LLM API
- JSON / SQLite
- GitHub Actions
- Slack
- FastAPI
- Streamlit
- BeautifulSoup / Playwright
- 공개 채용 API
- Tableau 또는 별도 Dashboard

기술은 기능을 구현하기 위해 필요할 때 선택한다.

## 12. MVP에서 하지 않을 것

- 모든 채용사이트 동시 크롤링
- 자동 입사지원
- 자기소개서 자동 제출
- 범용 사용자 계정 시스템
- 결제
- 모바일 앱
- 대규모 데이터베이스
- 합격 가능성의 확정적 예측

## 13. 개발 원칙

    문제 정의
    -> 가장 작은 동작 구현
    -> 실제 데이터로 테스트
    -> 결과 확인
    -> 문제 수정
    -> 기능 하나 추가

한 번에 완성형 서비스를 만들지 않는다.

## 14. 현재 구현 진척도

2026-09-14 기준 확장된 개인용 MVP의 전체 진행률은 약 78%로 판단한다. 이는 파일 수나 체크리스트 개수의 단순 비율이 아니라 사용자 가치와 남은 위험을 기준으로 한 추정치이며 약 ±10%의 오차가 있다.

- 데이터 구조와 근거 기반 매칭 엔진: 약 90%
- 자동 공고 발견, 중복 제거와 공식 ATS 상세 분석: 약 79%
- 명령행에서 실행 가능한 개인용 MVP: 약 90%
- 문서 업로드와 대화가 가능한 Slack 또는 Telegram Agent까지 포함: 약 44%

완료된 핵심 기반은 프로필 및 공고 구조, 요구사항·업무·지원 조건 비교, 지원 판단, 확인된 기술 부족의 결과물 기반 학습 추천, 기존 완료 프로젝트의 포트폴리오 개선 추천, 인크루트 RSS와 Greenhouse 공식 API 발견, 여러 보드의 전역 후보 1건 분석, 반복 분석 재사용과 실행 이력, 실제 검토 후보 10건의 메타데이터 큐, 미분석 후보 1건씩의 상세 분석, 명시적인 사용자 판단 기록과 후속 큐 병합, 사용자 문서 원본의 비공개 저장과 UTF-8 텍스트의 검토용 프로필 후보 추출이다.

MVP 완료 전에 반드시 필요한 항목은 다음과 같다.

1. 실제 공고 10건의 상세 분석과 사용자 판단 검토 계속
2. 추출한 프로필 후보를 사용자가 확인하고 승인 후보만 갱신안으로 만드는 흐름
3. 최소 Slack 또는 Telegram 대화 인터페이스

예약 실행과 자동 소스 확장은 개인용 명령행 MVP 이후에도 붙일 수 있지만, 최종적으로 요청한 자동 Career Agent 경험에는 필요하다.
