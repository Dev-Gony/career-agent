# Career Agent PRD

## 1. 프로젝트 개요

### 프로젝트명
Career Agent

### 한 줄 설명
개인의 성향, 경력, 기술, 프로젝트와 실제 채용공고를 비교하여 직무 적합도, 부족 역량, 학습 방향, 포트폴리오 개선 방향, 지원 우선순위를 제안하는 개인용 AI 취업 준비 에이전트.

### 현재 범위
초기에는 본인 1명이 사용하는 개인용 MVP로 개발한다.

실제 사용을 통해 유용성을 검증한 뒤 채용공고 자동 수집, 정기 브리핑, 시장 요구 역량 분석 등으로 단계적으로 확장한다.

## 2. 문제 정의

현재 취업 준비 과정에는 다음 문제가 있다.

- 어떤 직무가 나와 잘 맞는지 판단하기 어렵다.
- 성격검사, 적성검사, 경력, 프로젝트, 기술 정보가 여러 자료에 흩어져 있다.
- 채용공고마다 요구사항을 반복해서 읽고 비교해야 한다.
- 부족한 역량을 발견해도 무엇부터 보완해야 할지 결정하기 어렵다.
- 어떤 포트폴리오가 실제 취업에 도움이 되는지 판단하기 어렵다.
- 신규 채용공고를 계속 찾아보고 정리하는 과정이 반복적이다.

## 3. 핵심 목표

이 프로젝트의 목표는 다음 질문에 반복적으로 답할 수 있는 시스템을 만드는 것이다.

1. 이 직무가 나와 왜 맞는가?
2. 왜 맞지 않는가?
3. 현재 부족한 역량은 무엇인가?
4. 무엇을 먼저 공부해야 하는가?
5. 기존 포트폴리오를 어떻게 개선하면 되는가?
6. 지금 이 공고에 지원할 가치가 있는가?

## 4. 사용자

초기 사용자: 본인 1명

주요 관심 직무 후보:

- AI Automation / Workflow Engineer
- AI Solutions Engineer
- Forward Deployed Engineer 계열
- Enterprise Solution / ITSM / Workflow Automation
- Cloud / Automation
- Data + Automation 계열

직무 후보는 고정값이 아니라 실제 채용공고 분석 결과에 따라 계속 수정할 수 있다.

## 5. 판단 원칙

Agent는 다음 우선순위로 사용자 정보를 해석한다.

1. 실제 경력과 프로젝트
2. 실제 행동 사례와 문제 해결 경험
3. 기술 사용 수준과 증거
4. 직무/적성 검사
5. 성격 및 강점 검사

성격검사 하나만으로 직무를 추천하거나 배제하지 않는다.

궁극적인 사용자 인터페이스는 Slack 또는 Telegram 대화다. 사용자가 원하는 직무·경력 조건을 메시지로 설명하거나 이력서, 포트폴리오와 경력기술서를 첨부하면 Agent가 이를 비공개 사용자 프로필로 구조화한다. Agent는 그 프로필에서 검색 직무와 표현을 도출하고, 이용이 허용된 공식 API·RSS·기업 채용 소스에서 현재 공고를 발견하며, 적합한 공고와 판단 근거를 다시 대화로 전달한다. 사용자 자료에 충분한 근거가 있으면 직무 키워드를 매번 다시 요구하지 않는다.

## 7. 개인용 MVP 범위

첫 번째 실제 사용 버전은 Slack에서 본인 1명이 사용하는 Career Agent다. 사용자가 봇을 호출해 원하는 직무나 경력 조건을 설명하거나 이력서, 포트폴리오, 경력기술서, 직무분석표 중 한 개 이상을 첨부하면 Agent가 자료를 비공개로 구조화한다. 첨부자료 한 개만 있어도 시작할 수 있고 부족한 정보는 확인된 사실로 채우지 않는다.

Agent는 구조화된 사용자 프로필에서 검색 직무와 표현을 도출하고, 이용이 허용된 공식 API·RSS·기업 ATS 채용 소스에서 현재 공고를 자동으로 찾는다. 사용자가 채용공고를 복사해 붙이는 방식은 개발 중 분석 엔진 검증 수단일 뿐 최종 MVP 흐름이 아니다.

### MVP 입력

- Slack의 봇 호출 메시지
- 선택 입력인 원하는 직무, 경력 조건 또는 관심 방향
- 이력서, 포트폴리오, 경력기술서, 직무분석표 중 한 개 이상의 첨부자료
- 이전에 확인해 저장한 비공개 사용자 프로필

### MVP 출력

- 회사명
- 직무명
- 주요 업무
- 필수 역량
- 우대 역량
- 경력 조건
- 요구 기술
- 잘 맞는 부분
- 부족한 부분
- 직무 적합도와 근거
- 학습 우선순위
- 포트폴리오 개선 제안
- 지원 판단

### MVP 자동 발견 범위

- 정책을 확인한 공식 API 또는 RSS
- 공개 사용이 허용된 기업 ATS와 기업 채용 페이지
- 프로필 기반 검색 계획과 중복 제거
- 한 번에 관련 공고 한 건씩 상세 분석

사람인, 잡코리아, 인크루트, 원티드와 기업 채용페이지를 한꺼번에 우회 크롤링하지 않는다. 제공되는 공식 수단과 접근 정책을 확인한 소스부터 하나씩 추가한다.

## 8. 핵심 기능

### 기능 1. 채용공고 구조화

채용공고에서 다음 항목을 추출한다.

- 회사명
- 직무명
- 주요 업무
- 필수 조건
- 우대 조건
- 요구 기술
- 경력 수준
- 도메인 지식
- 협업 및 커뮤니케이션 요구

### 기능 2. 사용자 프로파일 비교

채용공고와 다음 사용자 데이터를 비교한다.

- 경력
- 프로젝트
- 기술
- 문제 해결 사례
- 업무 성향
- 관심 직무

### 기능 3. 적합도 분석

적합도는 숫자만 제공하지 않는다.

반드시 다음을 함께 제공한다.

- 높은 적합 근거
- 부분 적합 근거
- 부족한 근거
- 판단에 사용한 사용자 경험

### 기능 4. 역량 갭 분석

부족한 역량을 나열하고 우선순위를 구분한다.

예:

- 즉시 보완 필요
- 지원과 병행하여 보완 가능
- 우대사항 수준
- 현재 우선순위 낮음

### 기능 5. 학습 추천

학습 항목은 단순 기술 목록이 아니라 실제 결과물과 연결한다.

예:

    Docker 공부

보다

    기존 Tech News Automation을 Docker로 실행하고 재현 가능한 배포 구조를 만든다.

처럼 증명 가능한 결과물을 우선한다.

### 기능 6. 포트폴리오 추천

새 프로젝트를 무조건 추가하지 않는다.

우선순위:

1. 기존 프로젝트에 부족한 역량 추가
2. 기존 프로젝트를 더 깊게 개선
3. 그래도 증명하기 어려운 경우에만 새 프로젝트 제안

### 기능 7. 지원 판단

다음 중 하나로 제안한다.

- 적극 지원
- 지원 추천
- 조건부 지원
- 역량 보완 후 지원
- 현재는 우선순위 낮음

합격 가능성을 확정적으로 예측하지 않는다.

## 9. MVP 성공 기준

Slack에서 실제 사용자 자료 한 개 이상으로 프로필 생성부터 공고 추천까지 이어지는 전체 흐름을 확인하고, 실제 관심 채용공고 10개 이상을 분석한다.

다음 조건을 만족하면 다음 단계로 넘어간다.

- 결과를 읽고 지원 여부를 결정하는 데 실제 도움이 된다.
- 반복 분석에서도 비슷한 기준이 유지된다.
- 부족 역량 제안이 과도하게 넓지 않다.
- 학습 추천이 실제 실행 가능한 결과물과 연결된다.
- 포트폴리오 추천이 기존 작업과 연계된다.
- 사용자가 공고를 직접 복사하지 않아도 현재 공고를 발견한다.
- Slack 첨부자료에서 추출한 내용은 사용자 확인 전 실제 프로필 사실로 확정하지 않는다.
- 관련 공고가 없을 때 무관한 공고를 추천하지 않고 정상적인 빈 결과로 안내한다.

## 10. 이후 확장

### 2단계

채용공고 자동 발견 소스 확대

검토 대상:

- 사람인
- 잡코리아
- 인크루트
- 원티드
- 기업 채용 페이지
- 공개 채용 API 또는 데이터

현재 MVP의 공식 RSS와 기업 ATS 수집을 바탕으로, 각 사이트의 정책을 확인한 뒤 적법하고 안정적인 방식만 하나씩 추가한다.

### 3단계

정기 채용공고 분석

    신규 공고 수집
    -> 중복 제거
    -> 사용자 적합도 분석
    -> 추천 공고 선정
    -> 저장

### 4단계

정기 취업 브리핑

예:

    오늘의 추천 채용공고
    직무 적합도
    추천 이유
    부족 역량
    지원 우선순위

전달 수단 후보:

- Slack
- 이메일
- 웹 대시보드

### 5단계

채용시장 요구 역량 분석

누적된 공고에서 기술 요구 빈도를 계산한다.

예:

    Python 72%
    AWS 61%
    Docker 58%
    SQL 47%
    FastAPI 39%

이 데이터를 개인 프로파일과 비교하여 학습 및 포트폴리오 우선순위를 조정한다.

한 번에 완성형 서비스를 만들지 않는다.

## 14. 현재 구현 진척도

2026-09-15 기준, Slack 첨부자료 기반 개인용 MVP 전체 진행률은 약 67%로 판단한다. 이는 파일 수가 아니라 사용자가 Slack에 자료를 보내고 개인화된 공고를 받는 전체 사용자 흐름을 기준으로 한 추정치이며 약 ±10%의 오차가 있다. 이전의 94%는 명령행 분석과 Slack 연결 검증이라는 더 좁은 범위를 기준으로 해 궁극 목표의 진행률로는 높게 잡힌 수치였다.

- 데이터 구조와 근거 기반 매칭 엔진: 약 90%
- 허용된 소스의 자동 공고 발견과 상세 분석: 약 55%
- 비공개 사용자 문서 가져오기와 프로필 갱신 파이프라인: 약 60%
- 첨부자료와 자연어 대화를 포함한 Slack Agent 경험: 약 50%

완료된 핵심 기반은 프로필 및 공고 구조, 요구사항 비교와 지원 판단, 근거 기반 강점·부족 역량·학습 및 포트폴리오 제안, 인크루트 RSS와 Greenhouse 공식 API 발견, 중복 제거, 실제 공고의 1건 단위 상세 분석, 실행 이력, 사용자 판단 저장 경계, 문서 원본의 비공개 저장, UTF-8 텍스트의 검토용 프로필 후보 추출, 승인 기반 비파괴 프로필 갱신, 실제 Slack 인증과 Socket Mode 호출, 스레드의 분석 근거 및 원문 링크 응답, 실제 Slack 첨부파일 메타데이터 검증이다. Slack 인증 다운로드 코드는 합성 응답으로 검증했으며 실제 `files:read` 승인과 저장 확인이 남았다.

MVP 완료 전에 반드시 필요한 항목은 다음과 같다.

1. Slack 첨부파일 한 개를 안전하게 받아 비공개 문서 저장소에 연결한다.
2. 첨부자료에서 추출한 프로필 후보를 Slack에서 확인하고 실제 개인 프로필로 적용한다.
3. 갱신된 개인 프로필에서 검색 계획을 다시 만들고 공고 발견·분석으로 이어지게 한다.
4. 공식 수단을 사용할 수 있는 채용 소스를 단계적으로 확장한다.
5. Slack에서 추천에 대한 사용자 판단을 기록하고 실제 공고 10건 이상을 검토한다.

예약 실행과 정기 알림은 이 전체 흐름을 실제로 한 번 검증한 뒤 추가한다.
